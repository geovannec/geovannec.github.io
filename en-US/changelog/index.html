1.2.0 — Trust Release (Web-Origin Security, Quality Gates & OSS Health)

2026-09-30

Esta versão conclui os Sprints 30–34 do **Plano V4**: o servidor local em `127.0.0.1` passa a ser tratado como fronteira de confiança real contra páginas web maliciosas, a qualidade do código ganha gates objetivos de cobertura/mutação/snapshot, e o repositório recebe a infraestrutura completa de contribuição e supply-chain verificável.

Adicionado

— **Segurança web-origin (S30)**: origin gate anti-DNS-rebinding, CSRF synchronizer token 256-bit por lançamento, CORS same-origin sem wildcard, `X-Frame-Options: DENY` + `frame-ancestors 'none'`, step-up auth em ações destrutivas (rotação, panic wipe, export), rate limiting por rota e por relay, recusa de bind fora de loopback.

— **Quality gates (S33)**: `pytest-xdist` (4,2× speedup — 169s→40s), mutation testing `mutmut` com triage completa dos survivors (crypto 83,7% / governance 75,9% convencional), flaky-test hunter noturno com auto-issue, testes stateful Hypothesis de storage, golden tests de páginas + takeout, snapshot de OpenAPI (133 rotas), gates de cobertura por camada + `diff-cover ≥90%` em PRs, dataset demo determinístico (`tests/factories/` + `scripts/seed_demo.py`), harness de soak test (`scripts/soak_test.py` + workflow).

— **OSS health (S34)**: `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1), `SUPPORT.md`, issue/PR templates, `.github/labels.yml`, devcontainer, `justfile`, pre-commit (ruff pinado, mypy strict, REUSE 3.3 — 598/598 arquivos compliant, secret scan, commit-msg convencional), site docs MkDocs-Material com build strict no CI, processo de RFC (`docs/rfcs/`), índice de ADRs.

— **Supply chain (S34)**: todas as GitHub Actions pinadas por SHA, `permissions:` mínimas em todos os workflows, Dependabot (actions + pip, security updates ON), OpenSSF Scorecard + CodeQL (gated para repo público), **cosign keyless** do `SHA256SUMS.txt` (transparency log Rekor) e SLSA provenance preparada no pipeline de release; README ganha instruções de verificação SSH + sigstore.

Corrigido

— `OutboxQueue.pending_count()` não conta mais eventos que esgotaram retries (dead-letters) — encontrado pelo stateful Hypothesis.

— Rate limit: navegação GET em `/security/` não consome mais o bucket estrito de autenticação.

— Race xdist em testes E2E (seed por porta de worker); flake DNS em testes NIP-05/upload.

— Cobertura do branch `darwin` do sandbox de plugins testável em Linux (drift de gate macOS↔Linux).

— Removida dependência morta `bip-utils` (eliminou alerta Dependabot de `ecdsa`/Minerva).

Segurança

— VDP formalizado: SLAs (72h ack / 7d triage / 30d fix), coordinated disclosure ≤90d, hall of fame, CNA path via GitHub Security Advisories.

1.1.0 — V3 Release (Hardening, Extensibilidade & Launch Readiness)

2026-09-29

Esta versão conclui o **Plano V3** (Sprints 15–29): decomposição dos god objects, observabilidade opt-in, hardening de segurança e supply-chain, i18n, acessibilidade, conformidade legal, testes de caos, arquitetura de plugins com sandbox, revisão completa do namespace de event kinds Nostr (Protocol V2) e engenharia de release cross-platform.

Adicionado

— **Arquitetura (S15–S17)**: `events.py`/`routes.py` decompostos em módulos de domínio com registry-based dispatch; logging estruturado JSON com `request_id` end-to-end; connection pooling + LRU cache eliminando padrões N+1.

— **Segurança (S18–S19, S24)**: scan semanal de CVEs com SBOM e PR automático; fuzz de 10k+ iterações na desserialização de eventos; **rotação de chaves NIP-41** com expurgo atômico e recuperação social via Dead Man's Switch; harness de chaos relay (churn, relay malicioso, partição) — incluindo correção de *ID squatting* na deduplicação.

— **Global Readiness (S21–S23)**: i18n completo (pt-BR/en-US, plurais CLDR, RTL), gate de acessibilidade axe-core em CI, `PRIVACY.md`/`SECURITY.md`/guia de operador de relay, auditoria de licenças sem conflitos copyleft.

— **Extensibilidade (S25–S26)**: arquitetura de plugins em subprocesso com API capability-scoped (sem acesso a chaves/DB/rede); **Protocol V2** — renumeração de kinds para faixas canônicas NIP-01 com dual-read legado, conformidade NIP-88 (enquetes) e NIP-72 (moderadores), zero colisões de namespace.

— **Launch Readiness (S27–S29)**: crash reporting e métricas **opt-in, desligados por padrão**, anonizados e locais; verificação de update via GitHub Releases sem auto-install; builds PyInstaller para 3 OS com assinatura condicional e manifestos SHA256; auto-welcome configurável por comunidade; FAQ auto-responder 100% local; dashboard de engajamento para moderadores; auditoria de segurança V3 final sem findings críticos/altos; checklist de launch consolidado (`docs/LAUNCH_CHECKLIST.md`).

Corrigido

— Ordem dedup→verify na ingestão de relay (eliminou vetor de censura por ID squatting).

— Sanitização de `request_path` em crash reports (pubkeys em rotas como `/profile/<hex>`).

— Material de certificados de signing em `vars.*` migrado para `secrets.*` com cleanup garantido no `release.yml`.

1.0.0 — V2 Final Release (Sovereignty & Federação)

2026-09-28

Esta versão conclui o ciclo completo da **Fase V2** (Sprints 11 a 14), totalizando as 148 tarefas de engenharia previstas no plano de sprints. Traz a implementação completa de Web of Trust (WoT), criptografia NIP-44 v2, comunidades privadas com chaves simétricas de grupo, votações secretas commit-reveal, Dead Man's Switch, portabilidade total e cliente desktop nativo.

Adicionado

— **Web of Trust (WoT / S11)**:

— Algoritmo de fluxo de confiança determinístico com atenuação de distância exponencial e cache em SQLite.

— Filtro social anti-spam baseado em WoT com tolerância configurável (WoT threshold) por usuário e por comunidade.

— Painel visual de reputação exibindo distância de rede, conexões mútuas e caminhos de confiança.

— **Criptografia NIP-44 v2 & Comunidades Privadas (S12)**:

— Cifragem ChaCha20-Poly1305 + HMAC-SHA256 (NIP-44 v2) com isolamento temporal e derivação de chave HKDF.

— Comunidades privadas criptografadas (Kind 34550 privado) com envelopes NIP-17/44 e chave simétrica de grupo (Kind 10058) com rotação de época.

— Sistema de Match/Crush secreto (Kind 10054) com hash de compromisso cifrado e revelação mútua no perfil.

— Recurso "Quem visitou meu perfil" com eventos efêmeros opt-in e Ghost Mode com garantia de reciprocidade.

— Odômetro clássico de visitas com animação retrô no cabeçalho do perfil.

— Customização visual avançada de perfil (cores personalizadas, texturas de fundo e temas retrô Orkut).

— Respostas anônimas em tópicos (Burner Threads) utilizando chaves efêmeras isoladas por discussão.

— Cápsulas do tempo comunitárias com revelação programada no futuro (Time Capsule).

— **Federação & Governança Avançada (S13)**:

— Alianças e federação entre comunidades (Kind 34552) com compartilhamento de listas de bloqueio e moderação mútua.

— Cross-posting com atribuição e links cruzados preservando o contexto original.

— Calendário Comunitário de Eventos (NIP-52) com RSVPs públicos e exportação no formato padrão iCal (.ics).

— Feeds RSS e Atom nativos gerados dinamicamente para comunidades e perfis públicos.

— Votação verdadeiramente secreta (Secret Ballot) com compromisso SHA-256 e fase posterior de apuração (commit-reveal).

— Motor de busca semântico estruturado multifator (autor, intervalo de datas, comunidade, tags e kinds).

— Subfórum de Classificados/Mercado com campos estruturados para anúncios e negociações soberanas.

— Tópicos obrigatórios de apresentação de novos membros com liberação automática de permissão de escrita.

— Painel de membros ativos em tempo real via eventos efêmeros Nostr.

— **V2 Polish, Dead Man's Switch & Launch (S14)**:

— Dead Man's Switch (Kind 30040) com intervalo de heartbeat configurável e gatilho memorial com quórum M-de-N guardiões.

— Transição de estado de perfil para Memorial Mode imutável e somente-leitura.

— Histórico local de pseudônimos e aliases anteriores do perfil.

— Sistema de Fãs com contagem de prestígio e ranking de seguidores não-recíprocos.

— Auto-resposta configurável para novos visitantes de perfil.

— Takeout completo em arquivo ZIP contendo todo o histórico do usuário exportado em Markdown estruturado e arquivos de mídia.

— Tópicos especiais de Timeline/Changelog com marcos visuais para documentação de projetos comunitários.

— Indicador de saúde e descentralização de relays por comunidade com a mensagem canônica *"sua comunidade está em N relays ativos"*, badges coloridos e telemetria de latência.

— Aplicativo desktop nativo empacotado via PyWebView (`sovereign-desktop`) com servidor local Uvicorn integrado e fallback automático para navegador.

— Suíte completa de testes E2E cobrindo os 5 fluxos principais da V2 e auditoria de segurança criptográfica formal.

0.2.0 — V1 Release (Social Avançado & Fórum Rico)

2026-09-14

Consolidação da **Fase V1** (Sprints 7 a 10), trazendo a experiência completa das redes sociais nostálgicas com amizades assimétricas, álbuns, emojis NIP-30 e governança aprofundada.

Adicionado

— **Social Avançado (S7)**:

— Sistema de amizades e follows com distinção clara entre amigos mútuos, seguidores e ídolos.

— Mural de recados (Scraps) com suporte estendido a BBCode, Markdown e citações em cascata.

— Depoimentos com aprovação obrigatória do destinatário antes da exibição pública.

— Álbuns de fotos locais com compressão client-side e visualizador estilo galeria.

— Trilha sonora do perfil (YouTube / MP3 / SoundCloud embed) com reprodução retrô.

— Status em tempo real no perfil com emoticons clássicos.

— **Fórum Rico (S8)**:

— Emojis customizados por comunidade (NIP-30 Kind 30030) com auto-complete `:emoji:`.

— Fixação de tópicos (pin/unpin) com badge destacado de anúncio da moderação.

— Tópicos FAQ oficiais e wiki comunitária editável por membros confiáveis.

— Enquetes de comunidade com múltiplas opções, votos únicos e contagem ao vivo.

— Tags populares da comunidade e navegação lateral por categorias.

— **Governança & Moderação V1 (S9)**:

— Sistema de recursos (appeals) para usuários moderados recorrerem a decisões de quarentena.

— Petições de revogação de moderadores (Mod Recall) por voto comunitário.

— Papéis customizados com cores e ícones por comunidade (Custom Roles).

— Slow mode dinâmico para controle de flood e rate-limiting de publicações em tópicos aquecidos.

— Bloqueio seletivo de links externos e domínios suspeitos por comunidade.

— **Polimento V1 (S10)**:

— Atalhos de teclado no estilo Google Reader / fóruns clássicos (`j`/`k` para navegação, `c` para novo tópico, `r` para responder).

— Acessibilidade WCAG 2.1 AA auditada em todos os componentes visuais e formulários.

— Benchmarks de performance: consultas SQLite abaixo de 10ms, FTS5 abaixo de 50ms e mineração PoW abaixo de 300ms.

— Auditoria de segurança formal da V1 validando isolamento de banco de dados e integridade de assinaturas.

0.1.0 — MVP Release (Fundação & Local-First)

2026-08-15

Lançamento inicial da **Fase MVP** (Sprints 1 a 6), estabelecendo a arquitetura do projeto.

Adicionado

— **Core Criptográfico & Protocolo Nostr (S1)**:

— Gerenciamento de chaves secp256k1 com derivação silenciosa via Argon2id + BIP-39 a partir de senha mestre.

— Serialização e verificação canônica de eventos Nostr (NIP-01) com assinaturas Schnorr.

— Suporte ao armazenamento seguro no chaveiro nativo do sistema operacional (`keyring`).

— **Camada de Dados & Rede Local-First (S2)**:

— Banco de dados local SQLite com Write-Ahead Logging (WAL) e migrações idempotentes.

— Fila de saída resiliente (`OutboxQueue`) garantindo operação 100% offline.

— Pool de relays WebSocket assíncrono com reconexão automática e telemetria de latência.

— Motor de busca em texto pleno FTS5 integrado com realce de sintaxe.

— **Identidade & Perfis Soberanos (S3)**:

— Perfis de usuário (Kind 0) com bio, avatar, localidade e campos de preferências.

— Mural de Scraps públicos e privados com paginação assíncrona HTMX.

— Top Friends (NIP-51) configurável de 4 a 16 contatos com ordenação drag-and-drop.

— Reações e reputação (+Rep / Thanks) via Kind 7 idempotente.

— Selo dourado de Pioneiro para contas dos primeiros blocos de usuários.

— **Fóruns & Comunidades (S4)**:

— Criação e governança de comunidades temáticas baseadas em NIP-72 estendido (Kind 34550).

— Tópicos de discussão com sistema de *bump* automático e ordenação dual (Bump vs Cronológico).

— Subfóruns categorizados e regras de conduta com aceitação obrigatória.

— **Governança Básica & Anti-Spam (S5 & S6)**:

— Proof-of-Work (NIP-13) client-side para mitigação de spam sem captchas centralizados.

— Account-Age Gate para restrição de publicações por idade mínima de conta.

— Denúncias descentralizadas (NIP-56 Kind 1984) e sistema de quarentena com tarjas de aviso.

— Interface Web nativa em FastAPI + Jinja2 + HTMX com modo escuro automático.
